# BiliBot 只读工具梳理报告

更新时间：2026-08-16

## 结论先说

WebUI 的“B站只读工具白名单”不是 AstrBot 所有工具的总开关，也不是普通插件配置列表。它的目的应该是：**只允许 B站评论/私信侧的安全上下文调用公开、只读、可审计的查询能力**。

此前页面把 AstrBot 当前注册表中的全部工具一起展示，导致用户看到很多与 B 站无关、或者即使与 B 站相关也不属于“只读”的工具。这会让人误以为这些工具都应该可以勾选。

本次 Fork 调整后：

- 可选择区域只展示已经提供 B站只读适配器的工具；
- 其他工具移动到折叠的“其他已注册工具”说明区域；
- 保存白名单时，后端再次过滤，只接受 B站只读适配器名称；
- 写操作、私域记忆工具、复合主动行为工具不会进入只读白名单；
- `bili_parse_video` 不再被当作只读白名单工具，因为它被分层运行时归类为写/高风险能力，需要单独的能力控制。

## 这些工具为什么不可选

### `bili_action`

作用：执行一次明确的 B 站互动，例如评论、点赞、投币、收藏或关注。

不可选原因：这是**写操作**，会改变 B 站账号状态，必须经过管理员意图确认、写工具开关和能力票据，不应该通过“只读白名单”开启。

### `bili_bangumi`

作用：一个复合番剧入口，可以搜索、查看详情、查看排行、查看时间表、查询追番更新，部分动作还可能实际观看番剧。

不可选原因：它把多个读取和行为动作合并在一个入口中，权限边界不够细，尤其“观看”可能产生记忆、评分或后续行为。因此当前不作为 B站公开只读工具开放。

### `bili_block_user`

作用：按 UID 拉黑 B 站用户。

不可选原因：这是不可逆风险较高的账号写操作，只允许主人明确要求或确认时调用，不属于只读工具。

### `bili_recall`

作用：读取 BiliBot 的用户画像、会话、今日活动、视频、动态或番剧记忆。

不可选原因：这是**私域记忆读取**，不是公开 B 站数据。它需要绑定当前用户、会话和记忆 scope，不能作为所有 B 站评论/私信都能使用的公共只读工具。

### `bili_watch_videos`

作用：触发主动浏览 B 站视频。

不可选原因：这是主动行为入口，不只是读取公开信息。它可能触发视频分析、评分、评论、点赞、投币、收藏、关注或给主人分享，因此应该走主动行为和写操作策略，而不是只读白名单。

### 其他 40 个以上不可选工具

这些工具通常来自以下来源：

- AstrBot 内置工具，例如文件、Shell、系统或管理工具；
- 其他插件注册的工具；
- MCP 服务提供的工具；
- BiliBot 自己注册但属于写操作、私域读取或复合行为的工具；
- 当前工具管理器已注册，但尚未实现 B站专用安全适配器的工具。

它们显示出来的原因是旧版 WebUI 为了“真实展示 AstrBot 工具注册表”，把全量注册表直接放进了弹窗。它们**不是 BiliBot 只读白名单候选**，也不会因为出现在列表里就能被 B 站评论或私信上下文调用。

## 当前可作为 B站只读能力的工具

当前适配器白名单包括以下类型：

| 工具 | 作用 | 权限性质 |
| --- | --- | --- |
| `bili_up_info` / `get_up_info` | 读取公开 UP 主资料、投稿和动态 | 公开只读 |
| `bili_video_search` / `search_bilibili` | 搜索公开 B 站视频 | 公开只读 |
| `bili_search_and_watch` | 搜索并分析公开视频，不执行互动写操作 | 公开只读/媒体读取 |
| `watch_video` | 读取并分析指定 BV 号的视频 | 公开只读/媒体读取 |
| `check_following_updates` | 读取关注 UP 主的新投稿和动态 | 账号关联读取 |
| `check_following_live` | 读取关注账号的直播状态 | 账号关联读取 |
| `get_bangumi_info` | 读取番剧详情和剧集信息 | 公开只读 |
| `get_bangumi_trending` | 读取番剧或国创排行 | 公开只读 |
| `get_bangumi_timeline` | 读取新番时间表 | 公开只读 |
| `get_bangumi_updates` | 读取当前追番更新概况 | 账号关联读取 |
| `web_search` | 使用已配置的联网搜索后端读取公开网页 | 外部只读 |

“可作为只读能力”不代表任何通道都能直接使用。实际是否允许调用，还要经过：

1. B站端工具隔离开关；
2. 工具白名单；
3. 当前消息来源 scope；
4. 调用者身份和角色；
5. 提示词注入防护与审计策略。

## 当前工具注册与适配的区别

工具有三个不同概念，不能混为一谈：

- **AstrBot 注册**：工具出现在 AstrBot 的全局工具管理器中；
- **BiliBot 适配**：BiliBot 能够解释参数、限制结果并把调用绑定到 B 站安全上下文；
- **只读白名单可选**：工具同时满足只读、适配、当前可用，才允许加入 `BILI_TOOL_ALLOWLIST`。

因此，“已注册但不可用”是有意的安全状态，不是所有工具都需要补适配器。

## 是否有必要保留不可选工具

从运行安全角度看，**不可选工具不需要出现在“选择 B站只读工具”的主列表里**。但保留一个折叠说明区域仍有价值：

- 可以解释工具为什么不可用；
- 可以帮助管理员发现工具来自哪个插件或 MCP；
- 可以避免用户误以为工具发现失败；
- 可以在未来补充适配器时快速定位目标。

所以 Fork 版本采用“可选工具与不可用工具分离”的方案，而不是把全局工具注册表直接当成白名单。

## 后续建议

- 为每个 B站只读适配器补充参数 schema、调用示例和测试；
- 将写操作、私域读取和复合行为继续保持独立入口，不与只读白名单混合；
- 对 `bili_parse_video` 等可能触发外部发送或文件输出的能力继续使用能力票据；
- WebUI 只显示当前实际可选的 B站适配器，并用折叠区域展示不可选原因；
- 当适配器缺失时，明确显示“未提供适配器”，不要显示成可正常选择的能力。
