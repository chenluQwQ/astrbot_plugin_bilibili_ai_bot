# BiliBot 记忆数据模型与删除语义

本文记录当前实现中各类“记忆”的真实权威来源，供后续迁移和 Web 管理使用。
它描述的是数据职责，不代表所有数据都已经迁入同一张表。

## 当前数据职责

| 数据类别 | 当前权威来源 | 兼容副本或索引 | 唯一职责 |
| --- | --- | --- | --- |
| 对话、直播事件、主动视频语义记忆与压缩摘要 | SQLite `memories` | `memory.json` 是恢复/旧版本兼容快照 | 可按 scope、用户、评论线、视频和语义相关度召回的正文 |
| 记忆向量 | SQLite `memory_vectors` | `memory.json` 兼容快照仍可带旧向量 | 只负责语义检索；必须随正文更新和删除 |
| 用户画像、印象、标签、视频轻量关系、直播计数 | `user_profiles.json` | SQLite `profiles/profile_facts` 目前只供分层角色底座使用，尚不是完整镜像 | 描述“对这个人的了解”，不复制视频或直播正文 |
| Bot 长期角色/自我记忆 | `permanent_memory.json` | 无 | 受信入口写入的自我认知；外部评论、私信和弹幕不得直接写入 |
| 视频理解缓存 | `video_memory.json` | 部分可复用摘要会另写入 `memories` | 避免同一视频重复下载和分析；不是用户画像本体 |
| 永久视频去重 | SQLite `seen_videos` | `seen_videos.json` 是无容量上限的恢复副本 | 只记录 BV 与轻量观看元数据，永久回答“是否看过”；不保存正文和向量 |
| 互动反馈候选 | SQLite `feedback_candidates` | 无正文副本 | 只在回复发送成功后保存严格校验的短结论；供日报/周报聚合，不直接修改人格 |
| 视频偏好证据与状态 | SQLite `preference_evidence` / `preferences` | `preference_state.json` 是轻量恢复与同步副本 | 具体信号幂等入库；按候选、近期、稳定三阶段增强、保留、减弱或删除，包含负向偏好与审美疲劳 |
| 日报/周报结构化摘要 | SQLite `cycle_summaries` | `daily_summary.json` / `weekly_summary.json` 保持旧版兼容 | 自然语言报告与机器摘要分开保存；周报只组合每日结构化摘要，不重复灌入整周原始记录 |
| 每周近期人格区块与低频梗 | `personality_evolution.json` | 文件内 `history` 最多保留 12 个回滚快照 | 只保存可替换的近期状态/喜好/感想/合格反思及最多 2 个限时梗；绝不改写核心人设 |
| 主动看片详情 | `external_memory.json` | `watch_log.json` 只记活动流水 | 保存主动看过的视频、感想和互动结果 |
| UP 主关系 | `user_profiles.json` 的 `video_refs` | 视频记忆中的 `owner_mid/owner_name` 是检索元数据 | 只保存用户/UP 与视频的轻量关系，不复制视频总结 |
| 番剧进度与印象 | `bangumi_memory.json` | `bangumi_watch_log.json` 是活动流水 | 按番剧保存追番状态、分集记录和偏好 |
| 日报与周报 | `daily_summary.json`、`weekly_summary.json` | 各类 watch/reply/dynamic 日志是生成输入 | 保存已经生成的报告结果，不作为人物事实来源 |
| 跨插件记忆 | `BiliBotMemoryAPI` 最终写入 `memories` / `user_profiles.json` | 外部插件可以保留自己的事件 ID | 通过固定 API 跨插件读写，禁止直接修改 BiliBot 文件 |

`memory.json`、SQLite `profiles/profile_facts` 与若干活动日志目前仍处于渐进迁移阶段。
在迁移完成前，不能把两个不完整副本都称为权威来源，也不能由 WebUI 直接编辑文件。

## 稳定字段

新写入的语义记忆至少应具有：

- `rpid`：跨 SQLite 和兼容快照稳定的记忆 ID；
- `scope`：可见范围，例如评论、私信、直播、QQ 或公开视频；
- `memory_type`：事件、视频、直播、用户总结等明确类型；
- `actor_id/user_id`：记忆涉及的用户；
- `thread_id`：评论线、私信会话或直播场次；
- `target_id` 以及 `oid/bvid/room_id`：平台目标；
- `created_at`、重要度、层级和过期时间；
- 压缩摘要额外保存 `summary_kind` 与 `derived_from_rpids`，明确来源记忆。

新压缩摘要的 ID 由来源 `rpid` 集合生成，不再依赖秒级时间戳，因此并发压缩不会碰撞。

互动反馈候选使用平台事件键幂等去重。主人反馈权重为普通用户的 3 倍，熟悉用户略高；
熟人调侃可以被标注为 `teasing`，但不得据此生成反思候选。候选只保存“发生了什么、
哪里可能有问题、以后怎么做”的短结论，不保存模型思维链，也不会在写入时改变核心人设。

自动人格整理每个 ISO 周最多尝试一次，并且至少需要最近 8 天内的 3 个真实活动日。
它优先读取归档的结构化日报；日报关闭或缺失时，只从活动日志派生已经过滤私信正文与账号标识的
日结构。输入还包括偏好状态与达到门槛的反馈，不再读取最近若干条原始私信或聊天。
模型返回的反思文本不会直接采信：动态区块中的反思由已验证的纠正、批评、主人建议或
重复建议确定性重建。每次实际变化前保存快照，可用 `/bili性格回滚` 恢复上一个自动版本。
梗候选必须有两条可在输入中定位的证据，之后才允许同义合并和联网核验；到期后不再注入。

## 视频记忆的独立生命周期

视频记忆不套用普通聊天记忆的统一老化规则：

1. 看完后的前 15 天保留较完整的内容概括、感想和语义向量；
2. 15 天后转为低权重长期记忆，仍然可以在非常相关时被召回，但不应频繁挤进推荐；
3. 约 90 天后淡忘详细内容，压缩为视频标题、UP 主、分区以及“大概讲了什么”的短摘要；短摘要向量仍保留，但召回权重降到 `0.52`，只在高度相关时偶尔浮现；
4. 独立的 `seen_videos` 永久账本不存正文和向量，也不受 `watch_log.json` 的 200 条活动流水上限影响；
5. 按 BV 号明确查询时仍可看到观看痕迹，不会因为淡忘而误以为从未看过；自动选片、评论上下文和私信看片也不会重复下载分析；
6. 只有主人在 B站私信中明确要求“重新看一次/重看”时，才允许绕过去重重新分析；
7. `video_memory.json` 的详细内容采用同样阶段，避免完整分析永久堆积。

新视频经历还会保存 `score`、`score_reason`、`mood`、`review`、
`preference_signals` 和 `search_keywords`。喜好信号最多 5 个，按 UP、分区、作品、
人物、食物、音乐、游戏、技术、活动、地点或具体主题分类，并带正向、负向、疲劳或
好奇方向及视频内证据。它们首先只是一次观看证据，不会因为单条高分直接改写稳定喜好。

默认时间可在视频记忆配置中调整，但淡忘时间不会早于完整内容保留时间。
升级时会从 `watch_log.json`、`commented_videos.json`、`video_memory.json`、
`external_memory.json` 和已有视频语义记忆幂等迁移 BV；旧文件不会被静默删除。

## 删除操作的不同含义

### 单条记忆删除

- 删除指定 `rpid` 的语义记忆；
- 删除其 SQLite 向量和兼容映射；
- 从 `memory.json` 兼容快照移除；
- 递归失效明确引用它的压缩摘要；
- 清理用户画像中的直播 `memory_refs` 轻量引用；
- 不删除独立的用户画像事实、好感度、视频缓存和活动统计。

对升级前没有 `derived_from_rpids` 的旧摘要，按相同评论线、oid，或相同用户与 scope
保守失效。这样可能少保留一份旧摘要，但不会出现原文已经删除、摘要仍把它召回的情况。

### 按用户删除（待实现）

只删除该用户在指定 scope 下的对话/直播记忆和相关摘要，不应误删公开视频理解、
其他用户在同一视频下的评论，也不自动清空好感度或画像。

### 按视频删除（待实现）

删除该 `bvid` 的视频理解、语义记忆和相关摘要，并清除所有画像中的对应轻量视频引用；
是否删除视频下的用户对话必须在操作时单独选择。

### 清空画像（待实现）

删除指定用户的印象、事实、标签和关系引用，但保留对话历史。之后仍可从历史重新形成画像。

### 彻底遗忘（待实现）

删除指定用户的所有 scope 记忆、衍生摘要、画像、引用和可识别缓存，并同步计数与索引。
这是高风险操作，未来 WebUI 必须显示影响范围、二次确认并写入不含正文的审计记录。

## WebUI 接入门槛

在开放任何删除按钮前，后端必须先具备对应的单一服务方法、影响范围预览、权限校验、
审计和回归测试。WebUI 不得直接读写上述 JSON 或 SQLite 表。
