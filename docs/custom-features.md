# 浏览、图库与统一记忆扩展

本次扩展基于上游最新 main，合入维护版相对原始基线的功能增量，保留上游后台视频检查、工具权限、配置页、发送结果未知保护和现有许可证。

## 功能与入口

- **浏览记录**：聚合主动浏览、特别关注、主人 @、私信和工具看片的标题、观后感、公开评论、楼中楼回复与诊断信息；支持查看失败项。
- **评论图库**：从主动浏览的公开评论图片、关注动态中有界采集反应图，保存本地图片与描述；主动一级评论按文字含义及情绪语境选图，显示未配图原因。楼中楼使用原生表情，不上传图库图片。
- **图片历史**：评论记录保留发布状态、评论 ID、公开图片地址与选图过程；本地淘汰图片后保留文字经历与历史元数据。发送结果未知时不换请求重发。
- **原生表情**：热评回复按语气使用零或一个经过白名单校验的 B站表情，过滤未知代码、截断残留和严肃语境，记录实际使用的代码。
- **统一记忆**：可选连接 `astrbot_plugin_livingmemory`，同步观看、公开评论与回复等结构化经历，按事件键与内容指纹去重。记忆目标通过 `LIVINGMEMORY_SESSION_UMO` 指定，未填时使用已配置的主人会话。
- **公开资料**：通过 LivingMemory 的 `search_context` 请求 `purpose="public_comment"`，只接受已授权的知识库片段；服务不可用时返回空，不回退到私聊记忆。此功能要求 LivingMemory 支持资料授权接口。
- **视频分析**：增加字幕优先的低 Token 模式与带时间标记的分镜宫格模式，可选 ASR；保留传统分析路径及上游视觉策略。字幕噪声或证据不足时抑制主动公开评论。
- **配置与投递**：人设和模型提供商下拉、历史记忆向量补齐、UMO 旧格式补全、发送返回值校验、休眠后回复、浏览窗口延迟恢复、明确发送失败后的延迟重试、主人 @ 视频/帖子观后感与私信副本。
- **跨平台画像**：默认关闭。显式启用后只处理已绑定主人发言，脱敏后提炼事实并标注来源，不保存原始聊天正文；仍受现有记忆隔离规则约束。

## 预算、数据与兼容

图库上限 150 张，默认每天最多 12 次识图；每次浏览最多采集 2 张。直接匹配阈值默认 0.55；未命中时，对相似度至少 0.30 的至多 3 个候选做一次短文本判断，最多 8 秒、160 输出 Token、零 SDK 重试，失败时照常发送文字。

图库数据库、图片文件、同步状态、浏览与回复日志都在插件运行数据目录。新增字段兼容旧记录；旧评论缺少图片选择与表情字段时显示未记录，不伪造历史过程。请勿将运行数据、账号配置、密钥、数据库、日志或备份提交到仓库。

`USE_ASTRBOT_PERSONA` 接受历史布尔值，也接受空字符串（跟随默认）、指定人设 ID 和 `__off__`（关闭）。模型 ID 使用 AstrBot 已注册的提供商，包括路由型提供商。没有对应服务或模型时，功能按各自分支降级。

主人最近活跃群的推荐仅在分享方式为 `all` 且配置和历史记录仍属于同一主人时尝试；请按需要选择分享通道。主人 @ 观后感与跨平台画像均有独立开关。

## 验证与运行

开发环境需要 `pytest`、`pytest-asyncio`、`pydantic`、`Pillow` 等测试依赖，实际运行仍遵循上游 `requirements.txt` 和 AstrBot 环境；视频分析还需要服务器具备 ffmpeg/ffprobe 等既有媒体工具。

```bash
python -m pytest -q
node tests/test_extension_ui.cjs
node --check pages/bilibot/app.js
```

主测试命令会在独立子进程运行图库、图片历史与原生表情测试，避免 AstrBot 替身污染其他测试；全部使用模拟接口和临时数据，不发布真实评论。新增合并边界测试覆盖公开资料不带私聊会话范围、UMO 投递返回值、主人变更隔离及明确失败/未知结果的重试边界。

此合并版本尚未部署到生产环境。既有维护版的自然发布效果与本次合并后的离线回归是两种验证；离线通过不能证明每条自然评论都带图、每条楼中楼都带表情。首次安装或更新前备份运行数据；回退源码时保留数据目录，不覆盖整库。
