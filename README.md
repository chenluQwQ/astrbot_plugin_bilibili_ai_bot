# astrbot_plugin_bilibili_ai_bot

B站 AI Bot 插件 for [AstrBot](https://github.com/AstrBotDevs/AstrBot) — 让你的 AI 角色在 B 站评论区”活”起来。

从 2.0.0 起，插件围绕 Bot 的一天重新组织：睡醒、排日程、刷视频、回评论、记东西、夜里整理记忆。旧版本的配置和数据升级后照常可用。

## ✨ 功能

### 💬 评论与互动

- **评论自动回复** — 轮询评论通知，自动生成 AI 回复
- **@ 通知回复** — 有人在评论区 @Bot 时自动收到并回复（视频评论区 / 动态评论区都支持）
- **动态评论区回复** — 在你发布的动态下收到评论也会自动回复，不只限于视频评论
- **图片识别** — 评论中的图片自动识别内容后参与回复
- **视频上下文** — 自动获取被评论视频的信息，支持视觉模型分析视频封面 / 内容
- **联网查询** — 评论涉及时事、新知、特定事件时自动判断是否需要联网搜索，支持 Tavily / Firecrawl / Grok（xAI 原生 Web Search）/ Perplexity / 博查 / 自定义 OpenAI 兼容接口
- **B站私信回复** — 监听新的纯文字和视频分享私信；回复模型可按需调用工具查询UP/视频/番剧/关注动态或联网搜索（次数和评论区共用上限），要看视频时先短回应、看完再回复，最多发送两条；精确发送 `new` 可重置当前私信上下文
- **私信安全隔离** — 不明外链、IP 链接和疑似色情引流不会进入 LLM，可自动调用 B站拉黑；支持只回复主人、白名单或全部安全用户

### 🧠 记忆与人格

- **语义记忆** — Embedding 向量化 + 余弦相似度检索，支持记忆压缩、永久记忆（Bot 关于自己和主人的最多 8 条长期认知，回复B站评论、私信时可以自己增改删，默认只在和主人聊时；私信里记的不会出现在评论区和动态里）
- **好感度系统** — 陌生人 → 粉丝 → 熟人 → 好友 → 主人，不同等级不同语气；辱骂自动拉黑
- **用户画像** — 词条式档案：昵称、喜好、个人信息、标签、印象，以及轻量视频关系和直播互动统计。好感到过 `PROFILE_AFFECTION_LINE`（默认 20）的人，回复时顺手记下候选，每晚清算时由总结模型挑着整理进画像，评论和私信分开记
- **心情系统** — 每日随机心情 + 节日彩蛋（含农历）
- **性格演化（实验性）** — 旧版每日演化默认关闭且保留历史数据；建议积累真实反馈后再使用后续每周可回滚模式

### 🎯 主动行为

- **主动看视频** — 从关注更新、关键词搜索、视频池三条路径均衡选片，再评价、点赞 / 投币 / 收藏 / 关注 / 评论
- **一周分区口味** — 最近 7 天按分区汇总观看数和平均评分，交给 Bot 决定搜索词和标题筛选；仍允许自由探索其他内容
- **来源按当天数量均分** — 当天第 1 个取关注、第 2 个取搜索、第 3 个取视频池、第 4 个再回关注；分多次触发也承接当天进度，缺少候选时自动补位
- **给主人分享视频** — Bot 觉得某个视频适合主人时，可通过 B站私信发送推荐语和视频链接；也可改为评论区 @，或两者都发
- **自动发动态** — 定时发布动态，支持 OpenAI 兼容接口生成配图；手动 `/bili动态` 也可使用 NovelAI 官方生图
- **周总结图片卡片** — 从真实记录中挑选本周值得记住的片段，生成自然周记并渲染为自适应 PNG；QQ/B站动态优先发送图片
- **跨插件记忆接口** — 直播伴侣等插件可按 B站 UID 读取画像/语义记忆，并写入可检索的直播记忆
- **群聊/私聊B站分享解析** — 支持聊天链接自动识别、`/bili解析` 手动命令和 `bili_parse_video` LLM 工具三种入口，各自可独立启停；需要发送原视频时只提示“请稍等...视频一会发出”，随后直接发送视频/切片；解析后 Bot 用当前 QQ 会话的人格和模型自己决定看不看，看了会记住内容并引用该视频评价一句
- **看片前标题筛选** — 可让 LLM 根据标题/UP/分区/简介筛选搜索和视频池候选；关注与符合历史口味的候选直接放行
- **每日自主安排** — Bot 依当前人格和活跃度自行规划当天作息与行为节奏；可选休眠结束后生成或固定时刻生成，生成失败按间隔重试
- **行为安全上限** — 评论回复、私信回复、发布动态和主动浏览只设置每日硬上限，不设必须完成的数量；计划模型失败时当天不补造自动事件
- **可编辑主动浏览时段** — 支持配置固定主动浏览时间段并在面板内直接编辑，保存时校验时段长度、相邻间隔与休眠时间冲突
- **跨端活动同步** — 开启后把"正在挑选视频""正在分析视频"等当前活动同步给已绑定 `OWNER_MID` 的主人 QQ 私聊，行为结束即清除

### 📺 番剧能力

- **看番系统** — 支持搜索番剧、查看详情、完整观看单集内容
- **字幕 + 热评分析** — 自动读取字幕、热评、评论区与用户评价后进行 AI 分析
- **番剧记忆** — 看完后自动生成番剧记忆，可通过 `/bili番剧记忆` 查询
- **自动追番** — 评分达到阈值后自动加入追番列表
- **番剧更新查询** — 查询正在追的番剧是否更新
- **QQ 聊天看番** — 在 QQ 中直接让 Bot “去看番”

### 🔨 LLM 工具调用（v1.1.2 新增）

Bot 可在聊天中通过自然语言触发以下能力，工具结果回到 LLM 后由 Bot 用自己的话转述：

- **记忆查询** — `bili_recall` 统一查询用户画像 / 对话 / 今日活动 / 视频 / 动态 / 番剧记忆
- **B站搜索** — `search_bilibili` 搜视频、用户、UP 详情、公开收藏夹、关注更新与直播，用户说“我想看猫咪”就能推荐视频
- **看视频** — 去看一个视频、AI 分析内容、评分、存入记忆，看完可链式点赞 / 投币 / 收藏 / 评论
- **私信分享给主人** — `watch_and_share_video_private` 会先看完并写入视频记忆，再把B站原生视频卡片发给 `OWNER_MID`；默认关闭
- **互动操作** — `bili_action` 统一执行点赞 / 投币 / 收藏 / 关注 / 评论，需显式开启写工具，并由 QQ 私聊中的 AstrBot 管理员确认
- **番剧能力** — `bili_bangumi` 统一搜索、详情、观看、新番时间线、排行与追番更新
- **B站拉黑** — 管理员确认后拉黑指定 UID 的用户；确认只绑定当次工具和参数（v1.1.31 新增）

默认仅注册 8 个职责清晰的工具；开启私信分享开关时注册 9 个，减少工具说明占用和模型选错入口的概率。

#### 工具权限与写确认

- `ENABLE_LLM_TOOLS` 默认关闭。开启后，每次实际工具执行仍会读取真实 AstrBot 事件中的平台、发送者、会话与管理员身份；身份或会话缺失时默认拒绝，不信任工具参数、模型文本或记忆里的身份声明。
- **QQ 里默认只有管理员能让 Bot 调工具**；要让其他人也能用查视频、查UP、查番剧这类公开只读工具，开启 `SECURITY_ALLOW_NON_ADMIN_READ_TOOLS`。
- 工具按公开读取、私密读取和写操作分级。`bili_recall`、关注更新/开播、追番更新等私密读取还需开启 `SECURITY_ENABLE_PRIVATE_READ_TOOLS`；点赞、投币、收藏、关注、评论、拉黑、主动浏览和私信分享等写操作还需开启 `SECURITY_ENABLE_WRITE_TOOLS`。这几个安全开关都默认关闭。
- 写工具只对 QQ 私聊中的 AstrBot 管理员开放，QQ 群聊不开放。首次调用会返回写操作摘要；管理员在同一会话回复「确认」后，再以**相同工具和参数**发起调用才会执行，参数改变需重新确认，回复「取消」可放弃。模型自己生成“确认”不构成授权。
- 工具开关只决定是否允许调用，不会创建自动任务；视频解析、私信分享等功能仍受各自独立开关约束。

### 🛠️ 运维与安全

- **插件自定义代理** — 在 Web「基础设置 → 网络代理」填写 `PROXY_URL`，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`（支持 `socks5h://` 别名和 URL 账号密码）。填代理服务地址，不是订阅链接；仅使用你信任的代理。留空保持原网络行为，保存后重载插件使所有连接生效。
  - 覆盖本插件的 B站登录/评论/私信/直播请求、图片与视频下载、独立搜索/生图/视觉/Embedding API；不修改系统环境变量，也不修改 AstrBot 模型供应商或其他插件的代理。
  - 代理失败沿用原有超时、重试与冷却，不额外增加请求，也不会悄悄改为直连。只有填了代理才强制使用该出口。
  - Docker 中的 `127.0.0.1` 指容器自身；代理在宿主机时请使用容器能访问的宿主机地址。SOCKS5 依赖随插件 requirements 安装；手动覆盖文件的安装需同步更新依赖。

- **管理页** — 在 AstrBot 后台的插件页里，见下面「管理页」一节
- **隔离扩展 Host** — 可选插件通过安全 Page Schema 接入内置 WebUI；扩展缺失或异常时原功能不受影响，详见 [Extension API v1](docs/extension-api-v1.md)
- **LLM 熔断保护** — 单次调用不叠加重试；全局连续 5 次失败后默认冷却 2 分钟，恢复时仅放行一次探测，避免重复申请
- **基础防注入** — 对可疑 prompt 注入内容做检测、记录和安全包裹
- **写结果保护** — 评论、私信、动态及互动请求超时或中断时保留“发送结果未知”，不把它当失败盲目重试；拉黑、解黑和危险私信处理也区分真实成功、失败与结果未知
- **Cookie 自动刷新** — 定期检查 + 自动刷新，支持扫码登录
- **拉黑管理** — 手动 / 自动拉黑，黑名单用户不调 LLM 不花钱
- **恶意告警** — B站评论区有人攻击 Bot 时，用人设口吻通过 QQ 私信通知主人，主人可直接回复决定是否拉黑（v1.1.31 新增）
- **视频直读多格式兼容** — 视频分析支持 Gemini / Qwen 两种接口格式，用户自选（v1.1.31 新增）

## 🔗 QQ ↔ B站 记忆互通

跨平台共享默认关闭，只允许绑定到 `OWNER_MID` 的主人身份在显式开启安全共享后使用：

1. 管理员在 QQ 发送 `/bili绑定 <OWNER_MID>` 完成主人绑定；绑定主人 UID 需要管理员权限，普通绑定/解绑仍可自助
1. 将 `MEMORY_ISOLATION_MODE` 设为 `safe_share` 并开启 `ENABLE_SAFE_CROSS_PLATFORM_MEMORY`
1. QQ 对话只会收到经过脱敏、限长和类型过滤的B站侧近期摘要；插件不会反向保存 QQ 聊天记录

## 2.0.0 有什么新的

完整列表见 `CHANGELOG.md`，这里挑主要的：

- **回复前会查资料**：评论和私信回复前，模型可以自己连着查（简介、字幕、热评、联网、UP 主、番剧、Bot 自己的记忆），也能带着问题去看视频；查几次有上限，走 AstrBot 的工具调用

- **备忘录**：别人推荐的视频、番剧、UP 主，Bot 感兴趣就记一笔，排进之后的每日计划去看，三天没看自动过期
- **记忆重新整理**：记忆按视频、UP、人、系列打标签，找得更准；视频记忆慢慢淡成一句话印象；长期记忆只放要点（6 分以上的聊天和总结）；用户画像改成每晚统一整理，好感没到过门槛的人不留画像；Bot 可以自己维护最多 8 条永久记忆
- **看完视频怎么互动由 Bot 自己选**（投币、收藏仍要 8 分以上）；老是刷到又老是低分的 UP 暂时跳过；喜欢的系列会回去从第一季看
- **每周看一次公开收藏夹**修正口味；**找主人说**：碰到特别有感觉的评论私信在 QQ 跟主人说一句（默认关）；QQ 分享后偶尔问主人喜不喜欢
- **管理页重做**：白粉配色，总览先看 Bot 现在在干嘛，「今天」页是一条日记时间线，能删 Bot 自己发的评论；配置分「常用 / 高级」两层
- **数据都进了数据库**：原来几十个 json 搬进 `bilibot.sqlite3`，升级时自动导入，原文件不删；`/bili导出` 可以写回 json，`/bili清理旧` 把已导入的旧 json 收起来

## 总结、生成与行为节奏

新版本保留 AstrBot 人设，事实总结和角色表达可以选择不同模型：

| 用途 | 模型配置 | 负责内容 |
|---|---|---|
| 总结 | `SUMMARY_PROVIDER_ID` 或 `SUMMARY_API_KEY` + `SUMMARY_API_BASE` + `SUMMARY_MODEL` | 视频事实摘要、番剧内容、记忆压缩、日/周总结 |
| 生成 | `GENERATION_PROVIDER_ID` 或 `GENERATION_API_KEY` + `GENERATION_API_BASE` + `GENERATION_MODEL` | 视频评分感想、搜索方向、推荐文案、B站动态与自主日程 |
| 日程单独覆盖 | `SCHEDULE_PLAN_PROVIDER_ID` | 填写后优先于生成模型，用于今日计划 |

填写 provider ID 时优先使用 AstrBot 中的该模型；独立 API 是 OpenAI 兼容文本接口，填写密钥后必须填写模型名。两组全留空时沿用原 `LLM_PROVIDER_ID` / AstrBot 默认聊天模型。视频直读/截帧仍使用原 `VIDEO_VISION_*` 多模态设置，不能用纯文本总结 API 代替画面理解。独立模型失败时不悄悄切换到另一组 API。

推荐起步设置：`RECOMMEND_OWNER_MIN_SCORE=7`、`RECOMMEND_OWNER_DAILY_LIMIT=3`、`RECOMMEND_OWNER_MIN_GAP_MINUTES=120`。有具体看点才分享，同一 BV 的成功分享记录单独保存，重启或清理观看流水后仍可去重。升级不会覆盖你现有的 8 分/1 次或其他自定义值；希望增加推荐时请主动修改这些设置。

动态仍结合人设主动创作，但不是每天必发。每个定时时刻只是一次机会：先按 `DYNAMIC_POST_CHANCE`（默认 35%）决定这次要不要想，再由模型决定发不发，没有想说的就不发。`DYNAMIC_MIN_INTERVAL_DAYS=1` 表示定时动态每天最多一条，`2` 或 `3` 表示至少隔两天或三天。主动看视频时，模型可以给某个视频标注“想发动态”并写下想说的角度，一轮结束后为其中一个发动态（`DYNAMIC_FROM_VIDEO`），可选附上视频封面；这类动态不走概率和间隔，但仍受每日条数上限约束，同一视频只发一次。写动态前模型可以联网查资料（需开启联网搜索，`DYNAMIC_WEB_SEARCH_MAX` 控制次数）。默认可写的方向是分享日常、自我思考、吐槽近况、写段子和视频点评，可在 `DYNAMIC_TOPICS` 改写；`DYNAMIC_PROMPT` 可整段替换动态风格提示词，不伪造经历、不公开私密内容的规则始终生效。素材来自近期公开视频、番剧和动态记忆，不使用 QQ/私信聊天或主人的私密画像。手动 `/bili动态` 不受概率和间隔限制，仍遵守每日安全上限。`DYNAMIC_DAILY_COUNT=0` 表示这条不额外限条数（仍受自主上限和统一行为预算约束）；周报和日报动态是固定投递，不占用这条最短间隔。

已分析的视频再次出现在 QQ、B站私信或评论区时，优先使用原摘要、评分和感想；详细分析老化不会自动触发重看，也不会把这次回忆算成新的爱好证据。主人在B站私信明确说“重看”，或管理员在 QQ 明确要求“重新看”并调用观看工具时，才重新分析。只靠标题/简介生成的旧 QQ 预览会与真实观看记录区分；资料不足会说明尚未确认内容，不补造评分。

## 📦 安装

在 AstrBot WebUI 里通过网页单独安装。

或手动安装：

```bash
cd AstrBot/data/plugins
git clone https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot
```

## 🧩 依赖与环境

### 1. Python 依赖

插件内的 Python 依赖由 [requirements.txt](./requirements.txt) 管理：

- `aiohttp`
- `cryptography`
- `lunardate`
- `openai`
- `Pillow`
- `qrcode`
- `yt-dlp`

### 2. 外部命令依赖

以下是**独立的系统二进制**（不是 Python 包），必须额外安装，并且要能在系统 `PATH` 中直接调用：

- `ffmpeg`：压缩视频、抽帧
- `ffprobe`：读取视频时长，决定均匀截帧位置

安装方式：

|系统             |命令                                                                                                    |
|---------------|------------------------------------------------------------------------------------------------------|
|Ubuntu / Debian|`apt install ffmpeg`（自带 ffprobe）                                                                      |
|macOS          |`brew install ffmpeg`                                                                                 |
|Windows        |从 [ffmpeg.org](https://ffmpeg.org/download.html) 下载，或用 `scoop install ffmpeg` / `choco install ffmpeg`|

安装完成后在终端直接执行 `ffmpeg -version`、`ffprobe -version` 能正常返回版本号即可。

周报/日报图片无需另装中文字体。插件会优先使用系统里的微软雅黑、Noto CJK、思源黑体或文泉驿，并自带一份 Noto Sans SC 作为 Linux 兜底。只有想替换字体样式时，才需要在 `SUMMARY_CJK_FONT_PATH` 中填写 `.ttf` / `.otf` / `.ttc` 文件的绝对路径；所有字体都不可用时会自动退回文字总结，不会发送满是方框的图片。

> 💡 `yt-dlp` 已经作为 Python 包写在 `requirements.txt` 里，`pip install` 时会自动安装并注册命令，**不需要单独装**。

### 3. AstrBot 运行环境

- 建议使用较新版本的 AstrBot，本插件基于近期版本开发
- IM 平台方面**仅在 QQ 个人号（aiocqhttp）适配器上实际验证过**，其他平台理论可用但未测试
- 如果要让模型自动调用插件工具，聊天模型本身必须支持函数调用 / tool calling
- 如果要走 AstrBot 的多模态 provider，所选 provider 也必须支持图片 / 视频输入

### 4. 配置型依赖

- B站登录能力：`SESSDATA`、`BILI_JCT`、`DEDE_USER_ID`、`REFRESH_TOKEN`（用 `/bili登录` 扫码自动填）
- 文本 LLM：`LLM_PROVIDER_ID`，留空时会退回 AstrBot 默认聊天模型
- 视频视觉模型：`VIDEO_VISION_PROVIDER_ID` 或 `VIDEO_VISION_API_KEY + VIDEO_VISION_MODEL`
- 图片识别模型：`IMAGE_VISION_PROVIDER_ID` 或 `IMAGE_VISION_API_KEY + IMAGE_VISION_MODEL`
- 动态配图模型：`IMAGE_GEN_BACKEND + IMAGE_GEN_API_KEY`；NovelAI 留空模型名时用它自己的默认模型，OpenAI 兼容后端必须填写模型名，否则跳过配图
- 联网查询后端：`WEB_SEARCH_API_KEY`（按 `WEB_SEARCH_BACKEND` 选择 Tavily / Firecrawl / Grok / Perplexity / 博查 / 自定义）

### 5. 缺失依赖时的退化行为

- 没有 `ffmpeg` / `ffprobe` — 主动看视频无法做”视频直读 / 截帧分析”，会退回纯文本分析
- 没有视频视觉模型 — 视频分析退回纯文本概括
- 没有图片识别模型 — 评论图片识别功能直接跳过
- 没有图片生成模型 — 动态配图不可用
- 没有配置联网查询 — 评论回复不会触发联网搜索
- 聊天模型不支持工具调用 — `llm_tool` 不会被自动调用，但 `/bili主动`、`/bili记忆` 等命令仍可手动使用

### 6. 发布前自检

部署完成后，至少检查一次：

- `/bili状态`：确认 provider、外部命令、主动视频直读 / 截帧状态是否为 `✅`
- `/bili主动`：确认主动看视频能实际跑通
- 让 Bot 在聊天里执行一次记忆搜索或主动看视频请求，确认工具调用能触发
- 查看日志中是否出现缺少命令、模型未配置、provider 调用失败等警告

日志统一走 `/bili日志 <视频|番剧|动态|回复> [日期]`，例如 `/bili日志 视频 2026-07-01`。

评论区支持“按需资料”流程：同一个回复模型先看当前评论、对话记忆和已有观看记忆，选择直接回复、不回复，或先调用工具查简介、候选字幕、热评、联网搜索、带着具体问题检查当前视频。查询过程不会发送“我去看看”等中间评论。查资料走 AstrBot 的工具调用，**需要聊天模型支持工具调用**（AstrBot 模型提供商里勾上工具调用能力）；不支持时这一轮不查资料，直接回复或不回复。评论区和私信还都能查 UP（资料、热门投稿、动态、是否在直播）、按 BV 查视频资料、搜番剧、查 Bot 自己看过的视频 / 发过的动态 / 追的番（按对话所在的域过滤）。私信的文字消息也走同一套工具调用，次数共用 `COMMENT_CONTEXT_MAX_CALLS`，每条私信最多看一个视频；直播沿用原来的回复流程；评论区仍受原有过滤、概率和次数上限约束。

- `COMMENT_CONTEXT_ENABLED`：**B站评论回复前可以查资料**，默认开启。在 Web「回复与互动 → 回复前查资料」或「工具与安全 → B站评论和私信里的工具调用」设置，也可用 `/bili开关 查询` 切换。一个开关控制简介、字幕、热评、联网和视频核查；关闭后仍可根据已有记忆回复或保持沉默。
- `COMMENT_CONTEXT_MAX_CALLS`：每条评论最多查询次数，默认4，限制0～6；模型一次可以调好几个工具，次数按实际调用算，超出的不执行；相同查询不重复执行，视频检查最多2次。整轮（含查询和模型调用）有总时限，超时算一次模型失败，计入熔断。
- `ENABLE_MEMO`：备忘录，默认开启。回复时 Bot 对别人推荐的视频、番剧、UP主感兴趣可以自己记一笔（工具 `bili_memo`，评论里占一次查询次数）；好感为负的人推荐的不记，同一人每天最多 2 条（主人不限），待办上限 `MEMO_MAX_PENDING`（默认 20），3 天没做过期，夜里 Bot 会自己挑着丢掉不想看的。`/bili备忘录` 查看和删除。
- `ENABLE_BILI_EMOTES`：评论和私信回复可以在句末带一个B站小黄脸表情（`[doge]`、`[吃瓜]`、`[打call]` 等十几个通用的，列表在 `core/domain/emotes.py`），模型按语气挑，也可以不带；不在列表里的方括号代码发送前删掉，多的只留第一个。默认关闭。
- `COMMENT_WATCH_VIDEO_DAILY_LIMIT`：评论里有人丢来别的视频，Bot 可以自己决定去看（完整看片、写视频记忆），看完再回复；默认每天最多 3 个，每条评论最多 1 个，填 0 关闭。看片转后台，不挡别的评论；还要白名单 `BILI_TOOL_ALLOWLIST` 里有 `watch_video`（默认有）。
- 视频核查使用已有 `VIDEO_VISION_*` 配置；视频直读格式和中转接口须支持视频输入，否则使用抽帧。联网仍需开启 `ENABLE_WEB_SEARCH` 并配置搜索服务；旧搜索判断模型不再参与评论区这条流程。v1.7.1 起不再读取独立的 `COMMENT_VIDEO_INSPECTION_ENABLED`，统一由总开关控制。
- 定向检查可指定原视频起止秒数，每次最多检查180秒；长视频不指定范围时只检查开头、中间、结尾。保留源视频音轨，但音频是否被理解取决于模型和接口；抽帧没有声音。返回的时间戳是模型估计，“未观察到”不等于整条视频没有。
- 同一视频、同一问题和范围优先读取检查记录；通用总结未提到的细节不会被当成不存在。检查记录独立于原观看记忆，不修改评分、兴趣或已看视频账本。
- 查询日志记录查询种类、耗时和最终决定，检查日志保存问题、检查范围和证据（都在数据库的活动日志里，见下方「数据存储」）。下载和处理在独立临时目录中进行，完成或取消后清理。

管理员可运行 `/bili测试查询 BV号 [要核实的问题]`：不带问题时先尝试读取简介；也可以要求查字幕、热评或检查指定时间段。使用服务器实际配置的模型和资料服务，会产生正常调用费用；不发送 B站评论、不更新好感或画像，只返回回复预览和逐步调用日志。若模型直接决定而没有查询，会明确显示“未执行资料查询”，不会当成查询成功。测试不绕过总开关；开启但上限为0时仍不会执行查询。

用 `/bili日志 查询` 查看今天最近5条自主查询/只读实测记录，可加日期。日志区分资料查询成功、超时、次数用完、转后台、格式错误和最终是否生成回复；生成回复不代表已成功发布。只读实测会保存流程元信息，普通评论日志由 `BILI_TOOL_AUDIT_ENABLED` 控制。

今日计划生成模型在 AstrBot 原生插件配置中使用模型提供商下拉选择，留空跟随默认模型。


视频未能完成评价时显示“未评分”，并记录失败阶段、具体原因、模型提供商或模型名、评价耗时，以及可用的下载/视觉分析错误。更新前的旧失败记录无法补回原因。诊断随观看记录保存；不额外重试模型，也不保存提示词或模型回答原文。


> 💡 除了命令以外，也可以直接在聊天里用自然语言让 Bot 去随机看 B 站视频 — Bot 会用 LLM 判断意图后自动触发。

## 🌐 管理页

在 AstrBot 后台打开本插件的页面就是。不用另开端口，也没有单独的密码，跟 AstrBot 后台一样要登录。

- **总览**：Bot 现在醒着还是睡着、在干嘛、心情、今天看了几个视频；评论、私信、主动看视频今天还剩多少；接下来要做什么、运行状态
- **今天**：某一天看过的视频、发过的评论、看的番剧、发的动态，按时间排成一条；往前能翻 30 天。Bot 自己发的评论可以在这里删（要再确认一次；结果不确定时不会自动重试）
- **回复与互动**：评论回复、回复筛选、回复前查资料、备忘录和永久记忆、转告主人、私信、QQ 视频分享解析
- **主动与作息**：主动看视频、追番、发动态、看关注动态、特别关注、给主人分享这几张功能卡片，下面是活跃度、日程和每日计划
- **记忆与关系**：记忆数量、用户画像、好感度和心情、每周看收藏夹
- **工具与安全**：QQ 里能让 Bot 调用哪些工具、B站评论和私信回复时能不能查资料；下面是权限隔离、记忆隔离、恶意告警和自动拉黑
- **账号**、**基础设置**：登录和主人身份；人设和模型、记忆向量、视觉模型、联网搜索、日报周报等不常改的设置。不常用的项折在每组下面的「高级设置」里
- **全部配置**：所有配置按功能分类，主要功能在前、模型和系统设置在后，能搜。AstrBot 自带的配置页也是同样的顺序

## 🧱 代码结构

想改代码或写扩展的话，先看这里：

```
main.py            AstrBot 外壳：注册命令和钩子，转给下面
core/
  assembly.py      装配：创建所有对象
  runner.py        启停和主循环
  app.py           BotApp：WebUI、工具、QQ 命令只通过它用插件
  lifecycle/       主干：Bot 的一天（作息、活动状态、调度、分支之间的交接）
  features/        分支：评论、私信、主动看片、追番、动态、总结、QQ 分享……
  domain/          状态：好感度、记忆、心情、偏好、看过的视频……
  infra/           外界：B站接口、模型调用、视频下载、QQ 发送
  web/ tools/ commands/   WebUI、LLM 工具、QQ 命令
```

依赖只能往下走：分支之间不互相调用，domain 之间不互相调用，有事经主干交接。`tests/test_import_direction.py` 会检查。

## 📁 数据存储

插件数据存储在 `data/plugin_data/astrbot_plugin_bilibili_ai_bot/` 目录下，更新插件不会丢失数据。

从 v1.4.3 起，`bilibot.sqlite3` 是语义记忆主库，Embedding 单独保存在向量表；已有 `memory.json` 会在首次启动时自动导入，此后继续保留为兼容与故障恢复备份。请不要在插件运行时手工删除或替换这两个文件。

活动日志（看过的视频、回复、评论、动态、番剧、巡视关注动态、安全事件、主动触发、查询和检查记录）也存在 `bilibot.sqlite3` 的 `activity_log` 表里。升级后第一次启动会把原来的 `watch_log.json`、`reply_log.json` 等导入进去，原文件留着不删、之后也不再写；退回旧版本跑过一段再升级回来，会把旧版本新写的合并进来，不会重复。每晚清算删 30 天前的（每种至少留最近几百条），每种最多 3000 条，整体几 MB。`/bili清理 all` 立刻按这个规则清一次。想退回旧版本或自己备份时，`/bili导出` 把数据库里的按旧格式写回这些 json。数据库打不开时照旧读写 json。确认跑稳以后，`/bili清理旧` 可以把已经导入、之后没改过的旧 json 挪进数据目录下的 `old_json/` 文件夹（不删，先列出来，带「确认」才挪）。

去重账本（回复过的评论、处理过的 @、评论过的视频、语义去重库）同样搬进了 `processed_keys` 表，导入、导出、退回 json 的规矩和活动日志一样。回复过的评论和 @ 每晚只留最近 2000 个，评论过的视频不删。好感度、用户画像、里程碑、画像候选、QQ 绑定、番剧进度、视频记忆、外部记忆，以及心情、日程、日记周记、永久记忆、各种冷却和游标这些小状态，也都在数据库的 `keyed_json` 表里，规矩相同。只有联网缓存、yt-dlp 更新记录还是 json（删了也无所谓）。

视频记忆默认按三个阶段保存：`VIDEO_MEMORY_DETAIL_DAYS`（默认 15 天）内保留较完整的分析与感想；之后回复时少用；到 `VIDEO_MEMORY_FADE_DAYS`（默认 90 天）后正文只留 BV 号和看完时写的一句话印象（很喜欢的多留一句感想），并以极低权重保留语义向量，只在高度相关时偶尔想起。评分低于 `VIDEO_LOW_SCORE_FORGET_BELOW`（默认 5）的视频记忆满 `VIDEO_LOW_SCORE_FORGET_DAYS`（默认 30）天后整条删掉；淡成一句话的永久留着。

聊天记忆当晚由总结模型打 1–10 分，3 分以下不留；留下的 14 天后，6 分以上的进长期，其余留在近期。很久以前的（约半年）5 分以下闲聊会忘掉。同一个人、同一个评论区的聊天攒多了会压缩成一条总结。好感从没到过画像门槛的人，每晚清掉画像（留备份）。独立的永久 BV 去重账本保存在 SQLite `seen_videos`，`seen_videos.json` 是恢复副本；它不会按 200 条活动流水上限或时间裁剪。关闭 `ENABLE_VIDEO_LONG_TERM_MEMORY` 时仍维护分层缓存和永久去重记录。清理不会触及登录凭据、画像、好感度、日程和运行数据库。

主动行为的数量均按安全上限解释，不会为了凑数回复、评论或发动态。主动看片分别配置每日浏览轮次、每轮视频数、全天视频总数、单视频评论数和全天主动评论数；动态定时到达后仍会判断是否存在具体情绪、特别喜欢的视频或周回顾等真实发布动机，没有内容时保持沉默。

自动看片、特别关注、评论区视频分析和私信看片都会写入永久 BV 账本。再次遇到同一 BV 时只复用已有记忆；细节已经淡忘时也不会自动重新下载。当前仅允许主人在 B站私信中明确说“重新看一次”或“重看”来触发重新分析。

## ⚠️ 风险提示

- 使用本插件意味着 Bot 会使用你登录的 B站 账号进行自动化操作（评论、私信、点赞、投币、收藏、关注、发动态等），**存在账号被风控的风险**，请谨慎调节轮询间隔、主动行为频率
- 建议不要用主号测试，必要时准备小号
- 请合理配置 `POLL_INTERVAL`、`PROACTIVE_VIDEO_COUNT` 等参数，避免高频请求
